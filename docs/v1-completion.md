# V1 实施与验收台账

基线：`f09b846`。范围沿用总体设计 V01–V32、工具 T01–T15、MCP M01–M20；不包含后续租户与平台远程执行。

此台账区分实现和验证，未经过目标系统验证的能力不标记为已交付。源码留在用户当前工作目录，后续提交在 `feat/complete-v1`；不改动现有本地账号、模型配置或会话。

## 实施顺序

1. 原生执行：平台策略与能力报告，真实隔离探测，受管进程生命周期，命令输出与取消，Runtime/权限/UI 接线。
2. 文件与上下文缺口：安全路径操作、正则搜索、目录指令、预算与恢复复核。
3. 插件：Provider 路由、用户命令、状态与生命周期验证。
4. MCP：受管 stdio、凭据存储与 Bearer/OAuth、Prompts、交互续交、协议回归。
5. 交付：备份恢复、诊断、打包/安装/升级、真实模型闭环、目标平台验收。
6. 对照全部验收项复审，修复遗漏，更新支持矩阵。

## 实施记录

- 起点：85 项核心测试、8 项 PostgreSQL 集成已有通过记录。本次按新增行为运行针对性测试和全量相关检查，旧记录不作为新增能力的验收。
- 预检：ProcessService 由 Runtime 按 turn 创建；平台启动器只负责隔离与执行域，命令服务负责输出/超时/持久化，ToolExecutor 保持协议转换。MCP stdio 复用同一启动器。
- 决策：保留已有工作目录和依赖，使用独立功能分支；避免迁移运行中的本地预览和私有数据库。源码变更保持逐批可回滚。
- 原生预检：本机 Seatbelt deny-default 加 process-exec/process-fork 仍允许 `setsid()` 成功；Darwin SDK 注明 NOTE_TRACK/NOTE_CHILD 自 10.5 起不再支持。仅杀进程组或依赖旧 kqueue 自动跟踪不能满足脱离进程组的子孙清理，命令入口继续保持关闭。Docker CLI 存在，但没有可连接的 daemon；本机没有 Windows 运行环境。
- 插件 Provider：完成显式适配器配置、按 turn 固定选择、压缩共用同一适配器、请求身份快照、插件缺失拒绝回退、Key 重新授权、流式凭据边界与取消。服务端可读取部署者预安装的纯 Provider 注册表；用户 HTTP 入口不能安装服务端代码。新增测试先复现默认适配器误调用及服务端运行位置未检查，再修复。
- Provider 验证：91 项核心测试、结构检查、类型检查、全部应用构建通过；9 项真实 PostgreSQL 集成通过。锁文件由 pnpm 离线重算，补全既有 esbuild/rolldown 的跨平台可选包记录，没有升级依赖版本。外部真实厂商和三平台验收仍待执行。

任何剩余阻碍必须记录实际缺少的环境或凭据；不得以模拟后端、隐藏入口、空实现或减少设计范围完成勾选。

- 插件用户命令：完成 schema 注册、显式用户入口、按 Session 排队与请求去重、身份在线校验、无模型执行、工具委托、结果产物与时间线投影；桌面表单和 CLI 交互/非交互均接通。Chat 命令不具备 Agent 工具能力。
- 生命周期复查：新增回归复现了关闭的 ToolExecutor 仍接受迟到写入，现已在关闭时撤销执行范围并等待在途调用及委托回执。插件回调超时/结束/取消后同样撤销委托范围。根 UI 的重复提交与创建会话抽到 useSessionSubmission，turn 工具装配抽到 turn-tools。
- 命令验证：96 项核心测试、结构/类型检查、全部应用构建通过；10 项真实 PostgreSQL 集成通过，其中真实 CLI 经 HTTP 登录、重载已安装插件并在没有模型配置时创建 HTML。取消后迟到写入、只读委托及重复请求均有测试。UI 编译通过，当前工具环境仍未提供可用的桌面视觉检查。
- 文件检索：补齐单行 Unicode 正则、大小写选择、码点列号、上下文及截断；字面量仍按字面含义匹配。匹配仅在固定代码 Worker 处理文本数据，单文件 1 秒、Worker 堆内存 40 MiB 上限，取消/失败/完成均终止线程；文件读取仍走原有路径权限。100 项核心测试、结构/类型检查和应用构建通过，覆盖忽略规则、非法语法、零宽匹配、灾难回溯超时和取消。
- 项目指令：创建 Agent Session 时先验证并快照根 AGENTS.md；文件访问和搜索遍历发现子目录规则，每次模型请求前刷新已发现来源。每个版本保存 path/scope/hash/contentObjectId/sourceType/revision，最多 32 文件、累计 64 KiB；超限明确失败。写入前（包括插件审批返回后）发现版本变化会返回 INSTRUCTIONS_CHANGED，不产生文件修改。Chat 不读取本地指令。
- 指令并发：真实并行插件读取复现了两个来源的快照互相覆盖，现将发现/提交串行化；跨 turn 重新加载已发现作用域，删除规则保留原始产物。根规则非法时不发布空壳 Session。
- 恢复复查：全量测试遇到 SQLite “statement has been finalized”；独立 Node 22 + --expose-gc 最小程序复现了 prepare().iterate() 的 statement 提前回收。MCP 恢复改为每页 500 条有界读取，补充 1020 条跨页事件的恢复和重复恢复测试。
- 本批验证：107 项核心测试、结构/类型检查、全部应用构建通过；10 项真实 PostgreSQL 集成通过。原生路径竞态加固和三平台命令执行仍未闭合；不将本批指令规则当作操作系统沙箱。
- MCP Prompts：完成有界 list、目录版本复核、参数校验、显式 get preview、完整文本快照、内容摘要确认、10 分钟有效期、请求去重、queue/steer 提交以及会话/配置绑定。模板中的 assistant 内容仅引用在用户材料中；不增加模型工具。Agent 桌面与 CLI 均接入，Chat 不接入。
- MCP 控制操作：预览请求由 MCP Runtime 持有、关闭及配置变更即取消；单独的取消入口不会把人工答复当作工具审批。预览/应用均经本地身份路由，不经 Praxis Server 转发模板内容。
- Prompts 验证：111 项核心测试、结构/类型检查、全部应用构建通过；11 项真实 PostgreSQL 集成通过。新 CLI 集成跨两个进程完成预览→退出→确认应用，再通过实际安装的 Provider 插件执行；确认期间没有第二次 prompts/get。新旧 MCP 协议、非法参数、目录变化、跨会话引用、非文本内容、重复应用和取消均覆盖。
- 下一切片边界：MCP 交互由 mcp-client 的表单转换/续交状态机管理，连接仍一操作一实例；Runtime 的提问/审批服务负责人工等待、身份校验、去重和关闭。使用 SDK 的手动 input_required 路径，避免自动续交越过字段预算与新参数审批；保留 SDK 传输、协议协商和请求 ID 生成。旧版服务端请求仅在同一连接的活动业务调用期间接纳。

- MCP 表单：完成手动 MRTR 续交、新 RPC ID、原样临时 state、8 次/12 字段预算、旧版活动调用关联、类型/约束校验、已知凭据和敏感字段拦截。每次新增回答使用具体参数的新审批票据；拒绝不自动重新询问，不保存 requestState。
- 人工控制操作：Runtime 增加独立于模型 turn 的交互范围；提示词预览可提问和审批，但不改变 Session 执行状态。取消、Host 关闭、配置变更和会话删除均关闭等待；重复相同答复/决定只返回持久回执，不产生新授权。问题等待的存储失败清理和同一会话冲突也已处理。
- CLI 与桌面：预览不阻塞 CLI 输入循环；表单失败可重新输入全部字段，关闭后不打印迟到预览。桌面预览在人工交互期间让出原有回答/审批卡片，选项提交真实 ID，断流快照会同步待回答问题。
- 本批验证：125 项核心测试、结构/类型检查、全部应用构建通过；11 项真实 PostgreSQL 集成通过。测试覆盖新旧协议、四种字段、秘密藏在未使用的答案文本、续交上限、状态-only、重复回执、预览取消和 CLI 输入可用性。实际桌面视觉验证仍受当前工具环境限制。
- 开发环境记录：离线完整安装因缓存缺少已锁定包失败，pnpm 移动的 22 个原依赖目录已恢复；新增 workspace 链接保留，锁文件用离线 lockfile-only 更新。恢复后重新通过全部核心检查和应用构建，没有升级依赖。

- 失败路径复查：新增回归复现工具扩展初始化失败时 ProcessService 泄漏，现于所有权转移前清理已获取资源；同步抛错的 close 不再阻止另一资源清理。清理无法确认时记录 cleanup_unknown 并以 interrupted 结束。插件最终响应检查按 JSON 编码比较 Key，覆盖含引号和反斜杠的凭据。
- 修复验证：129 项核心测试、结构/类型检查和全部应用构建通过；三种部分初始化/清理故障与编码凭据泄漏都有回归测试。

- 凭据切片边界：MCP client 下独立 credentials 模块拥有 OS helper/内存密钥与关闭状态，Host 拥有用户/客户端/服务器绑定及设置入口。macOS 使用 Keychain、Windows 使用 Credential Manager、Linux 使用 Secret Service 的 secret-tool；不可用时明确返回 memory 状态。原生 helper 仅通过私有 stdin/stdout 交换秘密，配置只记录随机引用、存储类型和认证 epoch。Bearer 接通后再扩展 OAuth 控制流程；未实测平台不标记完成。

- Bearer 凭据：已接通系统/内存 SecretStore、用户+客户端+Praxis 服务地址+MCP 端点+随机引用隔离、凭据轮换 epoch、配置后重新检查/启用、失效取消和本地清除。系统秘密通过 helper 的私有管道传输；配置只存随机引用。写入取消时尝试清理未发布项，超时不会假装内存保存成功。
- OS 证据：macOS 原生 Keychain helper 编译通过，实际写入→读回→删除与再次读取不存在均通过，未出现认证 UI。Windows Credential Manager 源码和 Linux secret-tool 适配已编写，但未在目标系统运行；继续单独记录为待验证。
- MCP 凭据边界：目录/资源/模板和最终响应在进入存储或模型前检查已知秘密；服务端业务 401 不自动重放。凭据改变使运行范围失效，旧目录 hash 与 authEpoch 不再可用。
- 用户入口：桌面独立密码字段和存储状态；CLI auth/clear-auth 以及 run --mcp-bearer-server 前台入口，一次性环境 Token 在启动 Host 前移除。后者支持系统存储不可用的机器，凭据退出失效。添加连接表单补齐 Prompts 能力选择。
- 本批验证：134 项核心测试全部通过（包括真实 macOS Keychain 测试），结构/类型检查、原生 helper 和全部应用构建通过；12 项真实 PostgreSQL 集成通过，新增 CLI/Host 测试完成临时凭据设置、前台 Agent 运行、退出后确认缺失。OAuth、stdio、原生执行沙箱、交付与平台验收仍未完成。
