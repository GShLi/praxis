# Praxis 第一版 UI 设计基线

日期：2026-11-03。用户已确认界面参考 ChatGPT、Codex；以下是适合 Praxis 既定能力范围的实现方案，不是像素复刻或已完成界面的声明。

## 1. 参考与整体方向

采用会话侧栏、中央对话流、底部输入区和按需展开的工作面板。ChatBot 保持简洁的阅读与问答界面；Agent 强调项目、执行进展、文件变更和用户控制。参考官方[会话与模式入口](https://learn.chatgpt.com/docs/quickstart)和[Codex 变更审阅](https://learn.chatgpt.com/docs/code-review?surface=app)提供的交互组织，使用“知行 Praxis”自己的名称与视觉标识。

第一版不因为参考产品有某按钮就增加对应能力。上传、语音、浏览器、自动化、云任务、Git 发布、后台开发服务器等未实现功能不显示为可点击的真实操作。

## 2. 三端布局

| 入口 | 布局与能力 |
| --- | --- |
| Web ChatBot | 左侧会话/新对话/设置；中央消息；底部输入框、模型选择、发送/停止；无 Agent 模式开关 |
| 桌面 ChatBot | 与 Web 共享对话组件，桌面顶部可切换 ChatBot/Agent；历史及请求由本地 Host 管理 |
| 桌面 Agent | 左侧工作区与会话；中央任务对话和执行记录；右侧可收起的变更/计划/输出面板 |
| CLI Agent | 文本会话和状态流；明确工具摘要、审批/问题、取消及错误；无全屏 TUI 前置依赖 |

ChatBot 会话不直接转换为 Agent 会话。切换模式回到各自最近会话或新建页；“交给 Agent”是用户选择后创建独立会话并复制所选需求。执行中的 Agent 不因切换到 ChatBot 停止，关闭应用按生命周期合同停止。

建议桌面基准为 1440×900：侧栏 248px，顶栏 52px，Chat 阅读区最大 760px，Agent 详情面板初始 360px。宽度不足 1160px 时详情切为可展开面板；不足 760px 时侧栏折叠为抽屉。布局可调整，不把这些数值作为平台硬要求。

## 3. 视觉与基础组件

默认跟随系统明暗主题，提供浅色/深色切换。浅色采用白色内容区与轻微灰色侧栏，深色使用分层中性灰；正文以清晰文本为主，边框和背景区分区域，避免装饰性渐变与大面积状态色。

基础间距以 4px 为单位，常用 8/12/16/24px；正文初始 14–16px、行高 1.6，代码使用等宽字体，字体优先系统字体。主按钮使用中性色高对比，绿色仅表示已验证成功，红色用于错误/拒绝，橙色用于待输入或状态需核对。

共用组件包括 AppShell、SessionSidebar、MessageList、MessageItem、Composer、ModelPicker、RunStatus、ToolActivity、ApprovalCard、QuestionCard、DiffViewer、OutputViewer、Settings。纯展示组件不读取数据库、不执行工具，桌面能力经主进程/Host 客户端注入。

## 4. ChatBot 完整流程

新对话页显示简短提示和输入框；首次未登录进入登录，未配置模型提示进入“模型提供商”。只维护一份提供商及 Key 设置，不按 ChatBot/Agent 拆入口。

发送后先显示待接纳状态，收到持久化 accepted 再成为正式用户消息。流式回复按 attempt/part 更新，终态事件替换临时内容；停止按钮表示请求取消，直到收到终态才显示已停止。断流保留已有正文并标明中断，可重生成最后一个回答。

Markdown 渲染禁用任意 HTML/脚本执行，代码块提供语言、复制和合理的横向滚动。回复中的 HTML 作为代码展示，不自动运行预览。复制成功、链接打开和错误均有简短、可访问反馈。

用户向上阅读时新输出不强制拉到底部，提供“回到最新”入口。发送 Enter、换行 Shift+Enter；中文输入法组合输入期间 Enter 不提交。输入草稿仅保存于当前用户/会话作用域。

## 5. Agent 完整流程

新任务先选择工作区，展示目录及当前权限预设，再输入任务。顶部持续显示工作区、当前模型、运行状态、取消入口；执行位置及权限范围作为用户判断依据，原始 RPC、epoch、内部表名等不进入日常操作。

任务时间线区分用户消息、模型文字、计划、文件修改、命令、MCP 调用和最终回答。工具项默认展示动作与结果摘要，可展开参数、输出和已保存 diff。模型流式输出中的“完成”不改变 RunStatus，状态只来自 Host。

运行中输入提供“追加指导”与“排队任务”两种明确操作，分别映射 steer 和 queue；已接纳但未领取的内容单独显示，不伪装为模型已经阅读。任务结束/重启后的旧待处理输入显示挂起，用户选择重新提交。

右侧变更页第一版读取本 Session 已保存的修改事实，支持文件列表、增删行、统一/分栏 diff 和复制路径；标明记录时刻与是否为历史快照。完整 Git 工作树审阅、stage/revert/commit 按钮不因参考 Codex 自动纳入。用户自己的 Git 操作仍可通过明确任务及权限流程执行。

输出页是已授权命令的结果查看器，第一版不是交互式 Shell；显示执行 ID 的友好标识、运行/退出状态、stdout/stderr、截断标记和取消入口。计划页展示版本化任务项，不用计划打勾代替实际成功证据。

## 6. 审批、提问、MCP 与恢复状态

| 状态 | 用户可见信息和操作 |
| --- | --- |
| running | 当前阶段、工具摘要、已用时间；可追加/排队/取消 |
| waiting_approval | 实际工具、命令/路径/目的地、申请范围、可用 diff；批准一次/拒绝 |
| waiting_input | 问题来源、选项/输入、发送给谁；回答/取消，不作为权限批准 |
| cancelling | 正在停止及尚待清理项；不提前显示已停止 |
| interrupted | 已保存历史、中断原因、未知效果；显式继续与处理挂起输入 |
| failed / unknown effect | 安全错误详情、已知变化和可行核查方向，不只显示泛化“运行失败” |
| completed | 最终回答、文件/产物入口与实际验证结果；保留未完成事项说明 |

审批和提问视觉分开。审批卡片没有默认自动同意，恢复历史中的旧卡片不可再次消费。键盘快捷键只作用于当前明确聚焦控件，不让编辑消息时的 Enter 意外批准操作。

MCP 设置包含服务器类型、配置、启用/禁用、连接测试、认证、能力与错误；工具调用显示服务器归属，资源和模板显示来源。OAuth 使用系统浏览器，界面只显示授权状态和掩码，不读回既有 token。

重启后首屏能看到中断任务，点击继续才创建新执行；旧审批关闭、未知远端结果保持需核对。退出时显示短暂停止进度，宽限内清理按 Runtime 合同处理，不用关闭动画掩盖残留任务。

## 7. 设置与账户

用户在实现阶段明确要求设置页面参考 ChatGPT，原先单一弹窗过于简单。设置改为独立页面：顶部返回入口，左侧分类与搜索，右侧分组表单、配置列表和行内编辑。打开设置不卸载应用会话状态，返回后保留当前会话及未发送草稿。

分类包括通用、模型提供商、Agent 与工作区、MCP 连接、插件、数据与隐私、账户与安全、关于知行。Web 隐藏本地 Agent/MCP/插件分类。通用设置提供主题预览、回答字号、发送快捷键、默认模型；桌面 Agent 权限区区分新任务默认值与当前任务权限。未接入的能力显示真实状态，不添加无作用的开关。

模型提供商采用同一管理页，新增/替换 Key 是只写操作，保存后仅显示已配置状态/掩码；配置冲突提示重新加载，不静默覆盖。MCP 服务凭据有独立归属，不能把它误认为模型 Key。

退出登录先停止本客户端活动任务，切换账号后清空当前显示及临时内容，再加载对应历史。诊断导出明确包含范围；失败信息不显示认证头、密码或原始秘密。

## 8. 可访问性与交付验收

首版支持键盘遍历、可见焦点、语义按钮、表单标签、减少动画和字体缩放。状态除颜色外提供文字；流式输出不逐字刷屏读屏通知，使用节流的状态区域。消息/代码可选择复制，长文本与空列表不会破坏布局。

验收使用真实视图组件及受控协议事件验证：无模型配置、空会话、长回复、失败、中断、审批、提问、命令 running/结束、MCP 不可用、重连重放及跨账号清理。测试数据与真实会话隔离，不让生产入口用计时器伪造执行结果。

UI 可以与核心开发并行，但交付必须接真实 Host/Server 事件。Web 不出现本地文件操作、桌面 Chat 不获得工具能力、未通过平台隔离验证的命令不能因 UI 按钮存在就执行。
