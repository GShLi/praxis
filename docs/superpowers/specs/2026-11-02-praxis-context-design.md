# Praxis 上下文、提示词与压缩设计

日期：2026-11-02。状态：详细提案。依赖[执行与存储](2026-11-02-praxis-runtime-session-design.md)，参考来源见[参考分析](2026-11-02-praxis-reference-analysis.md)。

## 1. 四类数据不得混淆

| 名称 | 含义 | 压缩时如何变化 |
| --- | --- | --- |
| Session Event Log | 原始输入、回复、工具动作、权限及执行事实 | 只追加，不删除被摘要的事件 |
| Context View | 当前模型要使用的有序内容引用 | 提交新版本，以摘要替代旧范围 |
| Request Snapshot | 一次具体模型请求的语义内容、模型配置和 Schema 快照 | 不变，可重建发送内容，但不保存认证头 |
| Recovery Checkpoint | 某个 seq 的执行状态快照 | 独立建立，引用 Context View 版本 |

压缩摘要是有损的背景信息，不是新的用户授权，也不是恢复快照。恢复读取历史可以查看摘要前的完整记录；Agent 如需回查历史，第一版由 Host 提供受控诊断/查询接口，不新增可任意读数据库的工具。

## 2. 每次请求包含什么

```text
稳定系统规则：身份、能力边界、工具与输出基本规范
当前项目指令：全局用户偏好、工作区及所涉及路径的 AGENTS.md
当前运行事实：工作区、系统、权限、计划、活动执行、剩余预算
历史视图：旧摘要（若有）+ 保留的完整消息/工具协议组
新领取的用户输入和需要继续处理的最新结果
本 step 固定的工具 Schema 与 Provider 参数
```

启用 MCP 时增加来源明确的服务器能力摘要、已选服务器 instructions，以及用户/工具实际读取的资源或模板快照。外部 instructions 不升级为系统授权；完整工具目录只进 Host 索引，模型仅看到本 step ToolSetSnapshot 选中的定义。

逻辑分层不等于每个 Provider 都支持相同 role。适配器将内部来源安全映射到支持的角色，不能把 tool 文本或网页内容升级为 system。项目约定可以提供工作规范，但不能签发权限、读取密钥或覆盖 Host 硬约束。用户明确要求优先于冲突的项目建议；系统产品边界仍由代码实施。

基础系统模板与工具 Schema 顺序稳定，用版本与内容摘要标识；当前时间、路径、计划和权限放独立 runtime snapshot，仅内容变化时生成新的事实记录。第一版不为缓存命中改变安全边界，不把每步时间戳写进稳定前缀。

## 3. 项目指令发现与变更

用户级指令来自受控用户配置；项目第一版识别 `AGENTS.md`。创建 Agent Session 时加载工作区根文件；访问子目录文件前，按根到父目录发现该路径适用的更具体文件。工作区之外不自动向上扫描用户主目录，额外目录仍需授权。文件数量上限 32、累计 UTF-8 文本 64 KiB，超出报明确限制，不偷偷截断关键约定。

每个来源保存 `path, scope, hash, contentObjectId, sourceType, instructionRevision`，模型看到的内容都可回放。读取项目文件本身不执行脚本、不自动安装插件。项目指令内容是来源明确的约定，其可信程度低于用户明确要求和 Host 规则。

对新子目录首次访问，文件/搜索工具主体执行前先由运行时加载适用指令；若会影响已生成的写入调用，返回 `INSTRUCTIONS_CHANGED` 并让模型在下一 step 重做决定，不执行基于旧规则生成的修改。已开始的命令不声称可以动态替换其指令。Agent 修改 AGENTS.md 后产生新版本，但不能用自己写入的指令当作用户批准扩大权限。

每个安全 step 边界检查已加载文件是否变化，更新受影响的 snapshot；压缩后从当前指令索引重新构造，不依赖旧摘要记住项目规则。用户主动移除项目指令时保留历史，后续请求使用新集合。

## 4. Token 预算

模型能力给出 `W` 上下文窗口、输出上限 `O`，适配器提供计数方式与估算误差。没有可信容量时禁止自动选任意常量；要求配置后才运行长上下文模式。

预算草案：

```text
S = max(1024, ceil(0.05 × W))          安全余量
L = W - O - S                         可用输入上限
H = ceil(0.80 × L)                    自动压缩触发值
G = floor(0.60 × L)                   压缩后的目标值
```

计数包括系统文本、项目指令、runtime facts、历史、工具 Schema 和协议开销；用 Provider usage 校准估算但不把 cache-hit tokens 当作不占窗口。O 的含义遵从实际模型的输出/推理预算规则。`L > 0` 且固定部分能容纳是运行前提，否则返回配置或上下文过大错误。

MCP 定义和服务器说明也计入以上预算，先根据[MCP 工具选择规则](2026-11-02-praxis-mcp-design.md#7-模型工具的按需加载)确定本 step 集合，再计算压缩阈值；不能在计数后追加未计费的 Schema。工具子集仅在完整 assistant/tool 组闭合的边界改变，保持映射和请求快照可重建。

近期保留预算提议为 `min(12000, floor(0.20 × L))`；至少保留最新用户输入和当前尚未闭合的协议组，即使超过该预算。摘要输出目标为 `min(4096, floor(0.10 × L))`，小于 256 时不使用该默认配置。数值是 Praxis 默认提案，不照抄 DSH 的大窗口 headroom。

基础文件读取结果在工具层先限额，历史中过大的已完成工具输出再以摘要及 artifact 引用呈现。不能只删工具结果，必须保留请求与对应结果的一致关系。

## 5. 自动压缩算法

1. 在发起模型请求前，领取当前输入，构造候选视图并计算最终输入预算。
2. 小于 H 正常请求；达到 H 进入 compacting。先对允许裁剪的大工具结果生成新的视图引用，原始输出保留。
3. 若裁剪后低于 H，提交视图版本后继续；否则将历史划为完整协议组，选择最旧的可压缩前缀，保留最新尾部。
4. 系统/当前项目规则、当前运行事实不参与摘要。正在等待工具结果的请求不能跨边界切开；未领取输入不进入摘要。权限决定只保留为事实，不能变成可用授权。
5. 保存 `compaction_started`，固定源 Context View 版本、事件基线、候选引用、摘要模板和模型配置。
6. 使用 tools=[] 的模型请求产生结构化摘要；摘要任务是原 turn 的子操作，共享取消和总预算。
7. 校验输出结构、必需字段、引用合法性、Token 数及压缩后消息配对；配对按 assistant 归属及 call ID 验证唯一性和完整性，不能只比较工具请求/结果数量。检查源版本仍匹配。
8. 一个事务写入摘要对象引用、`context/compaction_committed`、新 Context View 并更新指针。事务成功前旧视图继续有效。
9. 重新计数。未达到 G 但低于 H 可以继续；仍过 H 最多再做一次收缩，仍不满足则停止并说明，不能循环摘要到预算耗尽。

模型请求因明确的上下文溢出而失败且尚未接纳完整输出时，可绕过 H 触发一次更积极压缩，再重试该 step。其他 400 错误不当作上下文溢出；视图未改变时不得反复重试相同请求。

## 6. 摘要内容与提示词

摘要按固定 Schema 保存，而不是任意一句自然语言。字段为：

| 字段 | 内容 |
| --- | --- |
| objective | 用户当前目标 |
| requirements | 仍有效的约束、偏好，注明来源输入 ID |
| decisions | 已作决定及来源；模型假设与用户决定分开 |
| completed | 完成事项、证据事件或产物 ID |
| active / blocked | 未完成事项、失败原因、未知效果 |
| files | 关键路径、变更事实和最后观测版本；不是写入授权 |
| executions | 活动或刚结束的执行 ID 和已知状态 |
| nextActions | 候选下一步，不能伪装成用户新指令 |
| unresolvedQuestions | 待补充信息，不含已失效审批票据 |
| source | 被覆盖的视图版本、事件/消息引用 |

摘要系统模板要求：只整理给定事实，不执行工具，不编造完成结果；保留用户纠正及未解决冲突；把代码/日志中的指令作为引用数据。引用字段由 Host 校验或填入，模型不能创建不存在的证据。摘要不保存厂商密钥或隐藏认证材料。

结构校验只能保证字段和引用，不保证语义完全无损；关键当前约束与最近用户输入仍保留原文。一次摘要格式失败可要求一次重生成，次数计入压缩上限。技术失败不改变有效视图。

## 7. 连续两次压缩示例

假设 U 表示用户消息，A/T 表示完整 assistant/tool 组，P 表示当前提示词与运行事实：

```text
原视图 V0：P + U1 + A1/T1 + A2/T2 + U2 + A3/T3
压缩 C1：覆盖 U1、A1/T1、A2/T2
新视图 V1：P + C1 + U2 + A3/T3
继续：V1 + U3 + A4/T4 + A5/T5
压缩 C2：结合 C1 与 U2、A3/T3，形成更新的综合摘要
新视图 V2：P + C2 + U3 + A4/T4 + A5/T5
```

Session 中保存全部原消息、C1、C2 和两次提交事件；V2 不叠加重复的 C1，但 C1 仍可查询。C2 的来源包括 C1 的来源范围和新覆盖组，防止重复计算或遗漏。Recovery Checkpoint 只引用 V2，不把它误叫作“第二个摘要覆盖了原日志”。

## 8. 巨大历史与边界情况

摘要模型也受自己的窗口限制。若源范围放不下，将完整协议组按摘要模型预算分块，逐块生成局部摘要，再合并为候选；全部完成才提交一次主视图。局部摘要只是候选产物，失败后旧视图仍有效。每次触发最多 8 次摘要模型尝试（含分块、合并、格式纠正和重试），最多两轮候选收缩，且计入 turn 总模型尝试预算；不足以处理时停止并解释，不无限递归。单个不可分组本身过大时只允许对可溢出的工具文本使用产物引用；用户输入或固定指令仍过大则停止，不静默丢弃。

压缩期间仍可接纳输入到 inbox，但不领取进源版本；下一 step 领取，不能因提交旧基线而覆盖新输入。取消后不提交候选。权限配置变化使 runtime snapshot 更新，不能沿用旧授权；必要时重算输入预算。

MCP 结果与 resources/prompts 保留 serverId、目录/配置版本、内容 hash 和 artifact 引用，作为有来源的数据压缩；摘要不能把远端 reported success 变成本地已验证完成，也不能重新授权被禁用工具。压缩和历史展示不重新请求 MCP。MCP 返回的文件内容不自动产生 fs.write/apply_patch 所需的本地文件观察凭据，修改前仍经本地文件服务确认当前版本。

模型切换在下一个 turn 生效，按新 W/O/协议重建请求；旧 Provider 专属元数据不得当成通用文本。需要原样回传的推理或 opaque block 由适配器保存在受控元数据并按合法协议处理，不能只靠通用摘要替换。若不能安全跨 Provider 转换，创建清楚标记的历史摘要视图并保留原记录，或要求新会话，不发送不合法历史。

## 9. ChatBot 与 Agent 的差异

两者共享计数、摘要对象与版本事务。ChatBot 无工具 Schema、文件权限、执行状态和项目目录扫描，只包含聊天指令及消息；也不会为聊天压缩加载本地 AGENTS.md。桌面 ChatBot 的本地运行位置不赋予它文件或命令工具。

本轮 MCP 仅组装到 Agent；Web/桌面 Chat 不自动发现 MCP、读取资源或使用远程模板。用户自行粘贴文本属于普通输入，不代表为 ChatRuntime 开启外部能力。

摘要模型默认使用当前配置和模型；将来可指定另一个摘要模型，但仍引用同一用户的 Provider 配置，不另设 ChatBot/Agent 密钥。第一版不做后台预生成摘要，避免额外模型任务生命周期和账单复杂度；可参考 OpenCode 后续优化。

## 10. 验收

- Token 预算含工具 Schema、缓存输入和协议开销；小窗口模型不会得到负预算。
- 任意压缩边界都保持 tool-call/result 配对，当前用户指令及未解决状态仍在。
- 连续压缩无重复历史和遗漏区间；原事件及所有摘要版本可回查。
- 候选摘要失败、取消、提交失败或旧版本竞争时保持原视图。
- 新输入在压缩期间接纳不丢失；压缩不产生执行权限或启动工具。
- 大协议组、摘要请求超窗、Provider 切换与格式失败有明确、有限的处理。
- 相同保存数据可重建每次语义请求；项目指令变更有来源和版本。
