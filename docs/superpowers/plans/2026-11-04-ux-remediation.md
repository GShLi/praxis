# Web 与桌面端体验整改实施计划

**目标：**落实用户已批准的全部 UX 审查项，完善信息层级、操作路径、可读性、一致性与反馈状态。

**架构：**继续使用共享 React UI、Web/Local 客户端适配器与 Electron Host。草稿和导航由应用状态拥有；设置表单管理自己的异步状态；任务展示从权威会话快照派生。原始记录、凭据和权限边界保持现有协议。

**约束：**遵守 AGENTS.md，不引入 UI 框架，不修改真实用户配置与历史。桌面退出仍停止任务；确认仅用于防止意外丢失。使用本地 Git 身份分阶段提交。

## 实施与验收

- [ ] 会话草稿按身份、模式、会话隔离；新建与切换不丢输入，提交成功只清理被提交的版本。
- [ ] 首次使用展示模型/工作区准备状态，设置完成返回原草稿；登录说明 Key 获取路径并保留失败输入。
- [ ] 会话导航提供时间分组、状态、搜索与可恢复的归档管理；主页返回当前对话，不隐式新建。
- [ ] 任务持续显示状态、当前动作、耗时、待处理事项与文件结果；审批摘要中文化，保留完整参数。
- [ ] 文件变更支持任务文件汇总、行号与增删差异；加载/失败/重试清晰。
- [ ] MCP、插件编辑统一弹窗及取消/未保存/保存反馈；个性化离开与重新读取保护草稿。
- [ ] 设置明确账户/客户端/当前任务作用域；MCP、插件、Key 列表区分加载、空与失败并可重试。
- [ ] 统一辅助文字对比度、字号、中文状态、模型选择可读性、标题与控件尺寸及键盘焦点。
- [ ] 桌面存在运行任务时，关闭/退出提供确认；取消退出保留原任务，确认退出维持停止语义。
- [ ] 补充行为测试、执行结构/类型/完整测试/构建，并实测 Web/桌面关键交互、窄屏与明暗主题。

## 重点边界

异步发送时切换会话或继续输入不清错草稿；账号切换不混用草稿；取消编辑与网络失败不丢表单；已完成/失败/等待审批状态可见；文件差异超大时有界展示且说明截断；退出取消后应用仍可用。

## 模块归属

应用导航、草稿、首次使用、会话管理、桌面退出由主实现负责。设置整改集中在 `settings/`。工具、审批、差异与任务摘要集中在 `conversation/` 的独立组件。全局视觉与登录集中在 `styles/`、`auth/`。仅主实现合并结构例外并执行 Git 提交，避免并行修改公共记录。
